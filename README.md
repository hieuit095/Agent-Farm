## Overview

Farm-Agent is a highly advanced autonomous system designed to discover open-source GitHub repositories, identify bugs or quality issues, generate precise code fixes, and submit pull requests. Operating via a continuous loop or CLI, it acts as a polite, rigorous senior developer making tangible improvements to codebases.

## Key Features

- **Polyglot Sandbox Validation:** Uses isolated Docker containers to execute and validate generated patches (across Python, Node.js, Rust, Go, etc.) before any Pull Request is created.
- **DEV-QA Bounty Loop:** Employs an internal iterative loop where a "DEV" model generates code and a "QA" model critiques it, ensuring high-quality, complex patches.
- **Bloodhound Red Team:** An advanced code scanning phase integrating static analysis rules (ast-grep + Semgrep patterns) to find vulnerabilities and code quality issues.
- **Anti-Farming Filter:** A zero-tolerance gatekeeper that drops trivial findings (e.g., typos, formatting) and blocks documentation-only PRs to prevent spamming maintainers.
- **PR Patrol:** Autonomously monitors open PRs for maintainer feedback, uses an LLM to classify comments, generates code fixes locally, validates them, and pushes updates directly to the branch.
- **Super Human Mode:** A relentless, 24/7 autonomous daemon orchestrating Hunt and Patrol behaviors in a continuous Terminator execution loop.
- **Circular Target Loop:** A crash-safe, deterministic rotation system that processes targeted repositories loaded from a JSON configuration file.

## System Architecture (High-Level)

Farm-Agent orchestrates its pipeline via a rich command-line interface. Core features like the **Circular Target Loop** and **Super Human Mode** coordinate with an LLM Provider (e.g., Minimax or OpenRouter) and the GitHub API.

The system relies heavily on SQLite (`memory.db`) via `aiosqlite` for persistent state, tracking repositories, usage quotas, schedules, and active PRs. During operations, code vulnerabilities are identified by the **Bloodhound Red Team** analyzer. Fixes generated by the LLM are evaluated using the **DEV-QA Bounty Loop** and validated in a **Polyglot Sandbox** using Docker to ensure safety and correctness before any Pull Request is opened.

## Getting Started

### Prerequisites

- **Python:** 3.11 or higher
- **Docker:** 7.1 or higher (Required for Polyglot Sandbox Validation)

### Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/hieuit095/Farm-Agent.git
   cd Farm-Agent
   ```

2. Install the package and development dependencies:
   ```bash
   pip install -e .[dev]
   ```

### Environment Variables

Configure the agent using a `.env` file or `config.yaml`. The core required variables are:

- `GITHUB_TOKEN`: Your GitHub Personal Access Token.
- `MINIMAX_API_KEY`: Your Minimax API Key for LLM access.
- `OPENROUTER_API_KEY`: Required for OpenRouter LLM routing (used heavily in the Bloodhound audits).
- `MINIMAX_GROUP_ID`: (Optional) Your Minimax Group ID.

## Usage

Farm-Agent offers a set of robust CLI commands:

**Auto-discover repositories and create contributions:**
```bash
farm_agent run
```

**Target a specific repository directly:**
```bash
farm_agent target https://github.com/owner/repo
```

**Run the relentless 24/7 autonomous daemon:**
```bash
farm_agent superhuman
```
