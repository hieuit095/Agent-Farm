# Farm-Agent 🚀 — Architecture Blueprint

This file serves as a deep-dive architectural guide to the current raw reality of the Farm-Agent (`v3.0.0`) codebase.

## 1. System Overview & Tech Stack

| Component | Technology | Role |
| :--- | :--- | :--- |
| **Language** | Python 3.11+ | Core application logic. |
| **LLM Provider** | Minimax (Primary), OpenRouter (Fallback/Red Team) | Code generation, code analysis, and PR feedback response. |
| **Sandbox Environment** | Docker (7.1+) | Executes polyglot languages (Node.js, Go, Rust, Python) to validate code patches via a Sandbox Guillotine mechanism before PR submission. |
| **Static Analyzer** | Semgrep / Bloodhound | Pre-scans repositories for code-quality & security vulnerabilities. |
| **State / Database** | SQLite (`aiosqlite`) | Ephemeral (WAL mode) persistent memory storage (`memory.db`), caching analyzed repos, PR outcomes, findings, and more. |
| **CLI / Output** | Click + Rich | Powers the terminal UI, commands, and robustly formatted logs. |
| **Vector Store** | ChromaDB | Ephemeral RAM-only Local RAG engine for knowledge base lookups. |
| **Packaging / Build** | Hatchling (`pyproject.toml`) | Standardized python package management. |

## 4. Core Execution Loops / Entry Points

### A. The Terminator Loop (`SuperHumanLoop`)
Triggered via `farm_agent superhuman`. It executes a relentless, deterministic `while True` loop:
1. **Daily Reset**: Checks for calendar day turnover to reset quota trackers and execute KB garbage collection.
2. **Quota Check**: Asserts the daily max PR quota. If exceeded, it transitions entirely into `Patrol` mode.
3. **Pending Notification**: Immediately prioritizes PR Patrol if feedback has arrived on open PRs.
4. **Action Cycle**:
   - Executes `hunt` via a circular targeting sweep `_pipeline.run_circular()`.
   - After a hunt iteration, processes one round of `PRPatrol`.
5. **Cooldown**: Sleeps for a fixed interval between loops, completely stripped of any human-delay hallucinations.

### B. The `ContribPipeline.run_circular` (The Pipeline)
Executed per-repository as commanded by the Terminator loop.
1. **Selection**: Round-robins targets directly from `target_repo.json` (synced to the DB).
2. **Analysis**: Uses `BloodhoundAnalyzer` to scan the codebase.
3. **Gates & Pre-Filters**: Checks Anti-Farming compliance (rejects docs/formatting), AI usage policies, and private security disclosure boundaries.
4. **3-Cycle DEV-QA Loop**: Passes code generated by the LLM into the `DockerSandbox`. The patch is immediately applied to a local clone and tested. If failing, the system uses self-correction feedback and retries up to three times.
5. **PR Generation**: Safely dispatches the fix. If it's a high-priority flaw, it generates a standard PR. Otherwise, executes a "Route B" (Issue-First Protocol) polite issue request.

### C. PR Patrol
Periodically surveys open PRs. It reads the maintainer's review comments using the GitHub API, categorizes them, attempts to address the request via generating an immediate subsequent fix/commit, and updates the PR branch dynamically.

## 5. Database/State Schema (`memory.db`)

Farm-Agent utilizes `aiosqlite` with WAL mode persistence to remember its execution history and prevent re-analyzing repositories unnecessarily.

**Key Tables**:
- `analyzed_repos`: History of previously evaluated repositories to prevent repetitive scanning loops.
- `submitted_prs`: Record of created PRs with attributes indicating final status (`open`, `merged`, `closed`). Heavily used by `PRPatrol`.
- `findings_cache`: Caches vulnerability scanner outputs to save LLM tokens and execution time on subsequent runs.
- `run_log`: High-level operational timeline of script executions.
- `pr_outcomes`: Specialized tracking detailing specific outcomes of pull requests.
- `repo_preferences`: Caches style preferences derived from historical analyses to match styling formats.
- `blacklisted_repos`: Banned targets (due to toxic maintainers or explicit AI exclusions).
- `api_usage_log`: Logs LLM API token usages.
- `target_repos`: Directly populated from `target_repo.json`, tracks when repositories were last hit.
- `knowledge_base`: Cached snippets/lessons learned. Kept lean via daily GC sweeps removing stale items >90 days old.
